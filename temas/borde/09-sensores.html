El problema: fallas que nunca se vieron

Un motor, una bomba o un ventilador cambian su sonido y su vibración antes de romperse. Detectarlo a tiempo ahorra la rotura. Pero para entrenar un clasificador como el detector de personas harían falta muchos ejemplos de cada falla, y las fallas son raras y variadas.

La respuesta corta: se entrena una red solo con la máquina sana, para que aprenda a copiar su señal. Cuando la máquina se aparta de lo normal, la red no sabe copiarla y el error de la copia crece. Un umbral sobre ese error da la alarma. El ejemplo conductor es el detector de anomalías de MLPerf Tiny, que escucha autitos de juguete.

El detector visto desde afuera

Entra una señal de un sensor: el sonido de un micrófono o la aceleración de un acelerómetro pegado a la máquina. Sale un puntaje de anomalía, un número que crece cuanto más se aparta la señal de lo normal, y una decisión cuando el puntaje pasa un umbral.

Adentro: rasgos y un autoencoder

Las señales de una máquina son 1D: un valor por instante, no una imagen. Igual que con la voz del nivel 8, primero se cortan en tramas y se pasan a rasgos, números que resumen cada trama. En el ejemplo de MLPerf Tiny son 128 bandas log-Mel por trama de 32 ms. Con un acelerómetro se usan también la energía (RMS) y el espectro de la FFT.

Un autoencoder es una red con forma de reloj de arena. El codificador achica la entrada capa por capa hasta un cuello de pocos números. El decodificador intenta reconstruir la entrada a partir de ese cuello. Se entrena para que la salida se parezca a la entrada.

El cuello es la clave. Con 8 números no se puede guardar cualquier señal de 640: solo entra lo que se repite en los datos de entrenamiento, el "sonido típico" de la máquina sana. Una señal distinta no cabe en esos 8 números, y la copia sale mal.

analogía: un filtro adaptado

El autoencoder se comporta como un filtro adaptado a la señal sana: deja pasar casi intacto lo que se parece a lo que aprendió y rechaza lo demás. El error entre entrada y salida es lo que el filtro rechazó.

Recorrido: un clip de sonido

Seguimos el modelo de referencia de MLPerf Tiny con un clip de 10 s de un autito de juguete.

  1. Rasgos. El audio se pasa a un espectrograma log-Mel de 128 bandas, con tramas de 32 ms.
  2. Ventana. Se juntan 5 tramas seguidas: 5 · 128 = 640 valores, unos 160 ms de sonido. Es la entrada de la red.
  3. Copiar. El autoencoder pasa la ventana por cuatro capas densas de 128, el cuello de 8 y otras cuatro de 128, y devuelve 640 valores.
  4. Medir el error. Se calcula el error cuadrático medio (MSE): el promedio de las diferencias al cuadrado entre entrada y copia.
  5. Deslizar. La ventana avanza una trama y se repite. El puntaje del clip es el promedio de los errores en sus 6,4 s centrales.
  6. Decidir. Si el puntaje pasa el umbral, el clip se marca como anomalía.

Cómo se encadena: el umbral y el AUC

El umbral se fija con datos sanos: se miden los errores de la máquina funcionando bien y se elige un valor que pocos superan, por ejemplo el que supera solo el 1 %, el percentil 99. Así, con la máquina sana, la alarma salta en del orden del 1 % de las ventanas.

Para comparar modelos sin elegir un umbral, MLPerf Tiny usa el AUC (área bajo la curva ROC). Mide la probabilidad de que un clip con falla reciba un puntaje mayor que un clip sano tomado al azar. Vale 1 si separa siempre y 0,5 si adivina. El modelo de referencia da 0,88 en float32 y 0,86 cuantizado a int8; el mínimo exigido es 0,85.

Implementaciones reales: ¿hace falta el PIE?

Esta red es chica. Tiene 264 mil MAC por ventana, del orden del 4 % del detector de personas, y son capas densas. Por eso un micro sin unidad vectorial, como el ESP32-C6 (RISC-V de 160 MHz), alcanza para una ventana por segundo.

Muchos acelerómetros tienen una FIFO: guardan cientos de muestras solos mientras el micro duerme, y lo despiertan cuando está llena. Así el micro procesa la ventana de una vez y vuelve a dormir, igual que el nodo del nivel 7.

Relación con el resto del micro

El acelerómetro se lee por SPI o I2C (Microcontroladores, Tomo 3, nivel 2), y su aviso de FIFO llena entra por un GPIO de despertar. Las capas densas usan los mismos kernels de ESP-NN del nivel 1. El umbral y los votos siguen las ideas del nivel 6.

para llevar

  • Las fallas son raras y variadas: se aprende solo lo sano y se detecta lo que no se parece.
  • Un autoencoder copia su entrada pasando por un cuello chico; lo distinto no cabe y la copia sale mal.
  • El error de reconstrucción es el puntaje; el umbral se fija con el percentil de los errores sanos.

firmware · error y umbral en C

El error cuadrático medio entre la entrada y la copia, el umbral como percentil de los errores medidos con la máquina sana, y la decisión.

Lo probé con un caso de error conocido (MSE de 1) y con cien errores sanos entre 0 y 0,495: el percentil 99 queda en 0,49, un error de 0,8 da alarma y uno de 0,2 no.

ver el código 
#include <stdlib.h>

/* Detección de anomalías con un autoencoder: la red
   intenta copiar su entrada pasando por un cuello chico.
   Si la máquina suena como al entrenar, la copia sale
   bien; si no, el error crece. */

/* Error cuadrático medio entre entrada y reconstrucción. */
float error_mse(const float *x, const float *y, int n)
{
    float s = 0;
    for (int i = 0; i < n; i++) {
        float d = x[i] - y[i];
        s += d * d;
    }
    return s / n;
}

static int comparar(const void *a, const void *b)
{
    float x = *(const float *)a, y = *(const float *)b;
    return (x > y) - (x < y);
}

/* Umbral a partir de errores medidos con la máquina sana:
   el percentil p (por ejemplo 0,99) de esos errores.
   Ordena el arreglo que recibe. */
float umbral(float *errores_sanos, int n, float p)
{
    qsort(errores_sanos, n, sizeof(float), comparar);
    int k = (int)(p * (n - 1) + 0.5f);
    return errores_sanos[k];
}

/* 1 si el error supera el umbral: posible anomalía. */
int es_anomalia(float error, float u)
{
    return error > u;
}
