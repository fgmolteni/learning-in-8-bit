Oír una palabra

Cómo el ESP32-S3 escucha todo el tiempo y reconoce una palabra: micrófono PDM, tramas de 32 ms, el front-end de audio, el espectrograma Mel y WakeNet, con su carga de CPU y sus falsas activaciones.

El problema: escuchar sin parar

Un parlante inteligente tiene que reconocer su palabra clave, como "Hi ESP" o "Alexa", en cualquier momento. No puede dormir como el detector del nivel 7: el audio no avisa antes de llegar. Entonces el micro escucha todo el tiempo, y la red tiene que ser tan barata que deje lugar para el resto.

El ejemplo conductor de este nivel es WakeNet9, el detector de palabra clave de Espressif, en el ESP32-S3. La respuesta corta: el audio se corta en tramas de 32 ms, se limpia, se convierte en un espectrograma y una red de convoluciones dilatadas lo recorre. WakeNet9 usa del orden de 3 ms de CPU por cada trama de 32 ms.

La cadena vista desde afuera

Entra audio de un micrófono, 16 000 muestras por segundo de 16 bits con signo. Sale, en cada trama, una decisión: se dijo la palabra o no. Cuando aparece, el sistema despierta al resto, por ejemplo al reconocedor de comandos.

Adentro: del micrófono a la trama

Muchos micrófonos MEMS tienen salida PDM (pulse density modulation): un solo bit a un reloj de algunos MHz, donde la densidad de unos sigue a la presión del sonido. Es la salida de un modulador sigma-delta. El I2S del ESP32-S3 tiene un modo PDM a PCM que filtra y diezma ese tren de bits hasta muestras de 16 bits.

Las muestras se juntan en tramas: bloques cortos que la red procesa de a uno. En el S3, WakeNet9 trabaja con tramas de 32 ms, es decir, 512 muestras a 16 kHz. Una trama es lo bastante corta para que el sonido casi no cambie adentro y lo bastante larga para medir sus frecuencias.

El front-end: limpiar antes de escuchar

Antes de la red, el AFE (audio front-end) de Espressif prepara el audio. Cada bloque resuelve un problema distinto:

  • AEC (cancelación de eco): resta del micrófono lo que el propio parlante está reproduciendo, que el AFE recibe como canal de referencia.
  • NS (supresión de ruido): baja el ruido estacionario, como un ventilador o un motor, que no es voz.
  • BSS (separación de fuentes): con dos micrófonos, separa la voz buscada de otras fuentes.
  • VAD (detección de actividad de voz): marca en cada trama si hay voz.
  • AGC (control de ganancia): sube las señales débiles y comprime las fuertes.

analogía: la etapa de entrada de un osciloscopio

El AFE es como la etapa de entrada de un instrumento: acoplamiento, filtro y ganancia antes del conversor. Una red entrenada con voz limpia rinde mucho mejor si la entrada se parece a lo que vio al entrenar.

Recorrido: una trama se vuelve una columna

La red no mira las 512 muestras sueltas: mira cuánta energía hay en cada banda de frecuencia. Ese paso convierte cada trama en una columna de números, y las columnas, una al lado de la otra, forman un espectrograma.

  1. Ventana. La trama se multiplica por una ventana que baja suavemente a cero en los bordes. Sin ella, el corte abrupto agregaría frecuencias que no están en el sonido.
  2. FFT. La transformada rápida de Fourier pasa las 512 muestras a 257 frecuencias, de 0 a 8 kHz, separadas 31,25 Hz.
  3. Banco Mel. Unos 20 a 40 filtros triangulares suman la energía de grupos de frecuencias. Siguen la escala Mel, que imita al oído: filtros angostos en los graves y anchos en los agudos.
  4. Logaritmo. Se toma el logaritmo de cada energía, porque el oído percibe la intensidad en escala logarítmica y así un grito y un susurro quedan en rangos comparables.
  5. MFCC. Para obtener los coeficientes MFCC, una transformada coseno resume las bandas en pocos números poco correlacionados. Según su documentación, WakeNet usa MFCC.

Cómo se encadena: mirar medio segundo

Una palabra dura del orden de medio segundo, unas 15 tramas de 32 ms. La red tiene que mirar todas juntas. Una convolución común con filtros de 3 ve 3 tramas por capa, y para cubrir 15 harían falta 7 capas.

Según Espressif, WakeNet9 usa convoluciones dilatadas: en cada capa, el filtro de 3 mira valores más separados, 1, 2 y 4 posiciones. El alcance se duplica capa a capa, y con 3 capas una salida abarca 15 tramas seguidas.

Como la red avanza una trama por vez, solo calcula lo nuevo: las columnas viejas ya se procesaron. La decisión final promedia el resultado de varias tramas, igual que los votos del nivel 6, para no dispararse con un ruido corto.

El ESP32 no tiene PIE y su variante más grande, WakeNet5X3, ocupa 18 ms de cada trama de 30 ms. En el S3, WakeNet9 usa del orden de 3 ms por trama. El trabajo de Arm Hello Edge muestra el mismo diseño en un Cortex-M: MFCC y una red de convoluciones depthwise separables, con 95,4 % de acierto en su conjunto de prueba.

dato: el estándar de prueba

MLPerf Tiny mide palabra clave con Speech Commands v2: 12 clases (10 palabras, "desconocida" y "silencio") y una DS-CNN de 38,6 mil parámetros, que cuantizada acierta 91,6 %. El mínimo exigido es 90 %.

Relación con el resto del micro

El I2S y su DMA traen el audio sin la CPU (Microcontroladores, Tomo 3, nivel 3). La FFT y los filtros aprovechan el PIE, que también acelera las capas (nivel 3). Escuchar todo el tiempo impide el deep-sleep: el consumo es el de un núcleo activo (nivel 7).

N = fs · T; Δf = fs / N

N = 16 000 · 0,032 = 512 muestras (1024 bytes); Δf = 16 000 / 512 = 31,25 Hz

Con 20 filtros Mel, los centros de los primeros están a 3 frecuencias de la FFT uno del otro, del orden de 90 Hz, y los de los últimos a 28, del orden de 875 Hz.

T_trama

Para equivocarse una vez cada 12 horas, la decisión tiene que fallar menos de una vez cada millón de tramas: por eso se promedian varias.

para llevar

  • El micrófono PDM entrega bits; el I2S los vuelve muestras de 16 bits a 16 kHz, en tramas de 512.
  • El AFE quita eco y ruido, detecta voz y ajusta la ganancia antes de la red.
  • Ventana, FFT, banco Mel, logaritmo y MFCC convierten cada trama en una columna del espectrograma.
  • Las convoluciones dilatadas cubren medio segundo con pocas capas; la decisión promedia varias tramas.
  • WakeNet9 usa del orden del 9 % de un núcleo del S3, y falla del orden de una vez cada 12 horas.

¿Qué gana WakeNet9 con las convoluciones dilatadas?

firmware · piezas del front-end en C

La escala Mel de ida y vuelta, los centros de un banco de filtros expresados como frecuencias de la FFT, y la cuenta de tramas que entran en un tramo de audio.

Lo probé con 1000 Hz (da 1000 mel), con un banco de 40 filtros sobre una FFT de 512 a 16 kHz (filtros cada vez más anchos) y con las 49 tramas por segundo de Hello Edge.

ver el código 
#include <math.h>

/* Piezas de un front-end de audio para palabra clave. */

/* Escala Mel: separa los graves y junta los agudos,
   como el oído. 1000 Hz vale del orden de 1000 mel. */
float hz_a_mel(float hz)
{
    return 2595.0f * log10f(1.0f + hz / 700.0f);
}

float mel_a_hz(float mel)
{
    return 700.0f * (powf(10.0f, mel / 2595.0f) - 1.0f);
}

/* Centros de n filtros triangulares repartidos parejo
   en mel entre 0 y la mitad de la frecuencia de
   muestreo, expresados como bin de una FFT de n_fft. */
void centros_mel(int n, float fs, int n_fft, int *bin)
{
    float tope = hz_a_mel(fs / 2);
    for (int i = 0; i < n; i++) {
        float m = tope * (i + 1) / (n + 1);
        bin[i] = (int)(mel_a_hz(m) * n_fft / fs + 0.5f);
    }
}

/* Cuántas tramas de largo l con paso s entran en L
   milisegundos de audio. */
int tramas(int L, int l, int s)
{
    return (L - l) / s + 1;
}
