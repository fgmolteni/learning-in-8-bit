Del modelo al micro

El viaje de una red neuronal desde la PC hasta el ESP32-S3: cuantizar, empaquetar en un archivo que se lee desde la flash y un intérprete que llama, capa por capa, a la rutina más rápida disponible.

al terminar este nivel vas a poder…

  • Nombrar las seis etapas que llevan un modelo de la PC al micro y qué cambia en cada una.
  • Explicar qué hay en la flash y en la RAM cuando arranca el detector de personas.
  • Seguir una inferencia: el intérprete recorre el grafo y despacha cada capa a un kernel.
  • Distinguir un intérprete, un motor como ESP-DL y un generador de código.
  • Estimar cuánto cuesta el intérprete frente al cálculo de la red.

El problema: una red de la PC en un micro

Una red neuronal se entrena en una PC: un programa ajusta sus pesos, los números que multiplican a los datos, hasta que la red acierta. Los pesos quedan en float32, números con coma de 4 bytes cada uno.

El ejemplo conductor del tomo es el detector de personas: recibe una imagen gris de 96×96 píxeles y responde si hay alguien. Tiene unos 211 000 pesos, así que en float32 ocupa unos 823 KiB. El ESP32-S3 tiene 512 KB de SRAM, y además el micro calcula mucho más rápido con enteros de 8 bits.

La respuesta corta: en la PC la red se convierte a enteros de 8 bits y se guarda en un archivo de 294 KiB que el micro lee directo desde la flash. En el micro, un intérprete recorre la red capa por capa y llama, para cada una, a la rutina más rápida que tenga para ese caso.

La cadena vista desde afuera

Para el micro, una red es un grafo: una lista ordenada de operaciones, o nodos, conectadas por tensores. Un tensor es un arreglo de números con forma fija, como la imagen de 96×96 o los resultados intermedios de una capa.

La cadena recibe tres cosas: el grafo entrenado, unas cien imágenes de muestra para calibrar y la biblioteca de rutinas del micro de destino. Entrega dos cosas: un archivo con el modelo, que se graba en la flash, y el programa del micro con el intérprete adentro.

Adentro: las seis etapas

1. Entrenar. La red se entrena en float32 con imágenes etiquetadas. Para que entre en un micro se eligen arquitecturas chicas, como MobileNet, y activaciones simples como ReLU6, que se convierten fácil a enteros (Tomo 1, nivel 1).

2. Convertir. El conversor quita todo lo que solo sirve para entrenar y deja un grafo fijo. También funde capas: la normalización por lote multiplica y suma una constante por canal, y esa cuenta se puede meter dentro de los pesos y el bias de la convolución anterior. Así desaparece una capa entera.

3. Cuantizar. Cada peso pasa a un entero de 8 bits, int8, con una escala por canal (Tomo 1, nivel 2). Para las activaciones hay que conocer su rango, que depende de los datos. Por eso se pasan unas cien imágenes de muestra y se mide el rango de cada capa: es la calibración.

4. Empaquetar. El resultado se guarda en un archivo con formato FlatBuffers. En ese formato cada dato está en una posición fija, que se alcanza sumando un desplazamiento a la dirección del archivo. El micro puede leerlo en su lugar, sin copiarlo ni convertirlo. El archivo del detector ocupa 300 568 bytes.

5. Preparar. Al arrancar, el programa del micro registra las operaciones que el modelo usa, reserva la memoria de trabajo y deja que cada capa calcule sus constantes. Esto pasa una sola vez.

6. Invocar. Para cada imagen, el intérprete recorre el grafo nodo por nodo y ejecuta cada operación. Es la parte que se repite y la que mide la latencia.

analogía: la fresadora y su programa

El intérprete es como una fresadora CNC que lee su programa bloque por bloque desde una tarjeta. Cambiando la tarjeta fabrica otra pieza sin tocar la máquina; el costo es leer y decodificar cada bloque. Acá, cambiar el archivo en la flash cambia la red sin recompilar el programa.

Recorrido: arrancar e invocar el detector

Seguimos el ejemplo de detección de personas que publica Espressif para el ESP32-S3, con la biblioteca LiteRT Micro y los kernels de ESP-NN. Primero, lo que pasa una vez al arrancar.

  1. Ubicar el modelo. El programa toma la dirección del archivo en la flash. No lo copia a la RAM: la flash se ve en el mapa de memoria y se lee a través de la caché (Microcontroladores, Tomo 5, nivel 3).
  2. Registrar las operaciones. El programa arma una tabla con las cinco operaciones del detector: convolución, convolución depthwise, promedio, cambio de forma y softmax. Solo esas entran al programa, porque cada operación registrada ocupa espacio en la flash.
  3. Reservar la arena. La arena es un bloque fijo de memoria donde viven los tensores intermedios. El ejemplo reserva 160 KiB: 100 KiB para activaciones y 60 KiB de trabajo que piden los kernels de ESP-NN. Prefiere ubicarla en la PSRAM, la memoria externa.
  4. Preparar cada capa. El intérprete recorre el grafo una vez sin calcular. Cada capa reparte su lugar en la arena y calcula sus constantes, como la escala de cada canal. Así la inferencia no pierde tiempo en eso.

Después, para cada imagen: el programa copia los 9216 píxeles al tensor de entrada y pide una inferencia. El intérprete recorre los nodos en orden y, para cada uno, busca su operación en la tabla y la llama.

El despacho es la decisión dentro de cada kernel. En el código de esp-tflite-micro, la convolución int8 usa ESP-NN cuando la dilatación vale 1, es decir, cuando el filtro mira píxeles vecinos y no salteados. Si no se cumple, usa la versión de referencia en C, más lenta pero siempre correcta.

Al final, el tensor de salida tiene dos números: la puntuación de "hay persona" y la de "no hay persona". El programa los compara y decide; el nivel 6 trata esa decisión.

¿Por qué el modelo no se copia de la flash a la RAM al arrancar?

Cómo se encadena: un costo fijo por nodo

La preparación pasa una vez y la inferencia muchas. Dentro de la inferencia, el intérprete agrega un costo fijo por nodo: buscar la operación, leer la descripción de sus tensores y llamarla. Ese costo no depende del tamaño de la capa.

Por eso pesa poco en una red de visión, con capas de cientos de miles de cuentas, y más en una red chica. Los autores de LiteRT Micro lo midieron: en el detector de personas el intérprete se lleva menos del 0,1 % del tiempo; en una red de palabra clave muy chica, del orden del 4 %.

Edge Impulse informa que su generador EON usa entre 25 y 55 % menos RAM y hasta 35 % menos flash que LiteRT Micro, con la misma velocidad: reutiliza los mismos kernels. La ventaja de generar código es la memoria, no el tiempo.

Los kernels sí cambian con la arquitectura. En el ESP32 y el ESP32-C3 (RISC-V) ESP-NN usa código C optimizado; en el ESP32-S3 y el ESP32-P4, las extensiones vectoriales PIE. En un Cortex-M, la misma tarea la hace CMSIS-NN de Arm, y con una NPU Ethos-U el compilador Vela entrega las capas al acelerador.

dato: formatos y estándares

  • FlatBuffers es un formato abierto de Google para leer datos en su lugar, sin copiar. Lo usan .tflite y .espdl.
  • ONNX es un formato abierto para intercambiar grafos entre herramientas. ESP-PPQ, el cuantizador de Espressif, parte de modelos ONNX, PyTorch o TensorFlow.
  • La especificación de cuantización int8 de LiteRT fija pesos simétricos por canal y activaciones con punto cero: el contrato entre el cuantizador y los kernels.

Relación con el resto del micro

El archivo del modelo vive en una partición de la flash o dentro del programa. Si está en una partición propia, se puede actualizar por radio sin tocar el programa (Microcontroladores, Tomo 1, nivel 6, ciclo de vida del firmware). La arena y dónde ubicarla son el tema del nivel 2.

Los kernels que elige el despacho son los que el nivel 3 abre por dentro. Medir cuánto tarda cada nodo es el tema del nivel 4.

El costo por nodo es fijo, del orden de miles de ciclos por inferencia. Solo se nota cuando la red entera dura poco.

S = treferencia / tESP-NN; cuadros por segundo = 1 / t

t_referencia
2300 ms (ESP32-S3 a 240 MHz, kernels en C)
t_ESP-NN
54 ms (misma placa, arena en PSRAM)

El mismo archivo y el mismo intérprete corren 42 veces más rápido cuando el despacho encuentra un kernel optimizado.

Límites y datos por confirmar

Los 207 968 pesos salen de la arquitectura publicada y no de leer el archivo; el modelo real puede diferir en detalles. Las mediciones del intérprete son de un Cortex-M4, no del ESP32-S3. Quedan por confirmar estos puntos:

  • el costo del intérprete medido en el ESP32-S3;
  • cuánta RAM ahorraría un generador de código en este detector;
  • las condiciones exactas de despacho de cada operación además de la convolución;
  • la cifra de 550 ms para el ESP32 que circula en algunos textos: Espressif publica 380 ms y no hay fuente para la otra.

para llevar

  • En la PC la red se convierte, se cuantiza a int8 y se empaqueta; en el micro se prepara una vez y se invoca para cada imagen.
  • FlatBuffers deja leer el modelo desde la flash sin copiarlo; la RAM queda para la arena.
  • El intérprete recorre el grafo y llama al kernel de cada nodo; el despacho elige ESP-NN o la referencia en C.
  • El intérprete cuesta poco en redes grandes; un generador de código ahorra memoria, no tiempo.

firmware · un intérprete mínimo en C

Este código muestra el mecanismo del recorrido, no el código de LiteRT Micro. Una tabla guarda un kernel por operación, que es lo que se registra al arrancar. La función de invocar recorre el grafo y llama a cada kernel. La convolución hace el despacho con la misma condición que esp-tflite-micro.

Con un grafo de prueba, las convoluciones int8 sin dilatación van a ESP-NN y la que tiene dilatación 2 va a la referencia en C.

ver el código 
#include <stdio.h>

/* Un intérprete mínimo: recorre la lista de nodos y llama
   al kernel de cada operación. Es la idea de LiteRT Micro,
   no su código. */
typedef enum { CONV, DEPTHWISE, PROMEDIO, SOFTMAX, N_OPS } Op;

typedef struct {
    Op  op;
    int es_int8;     /* entrada y salida en int8 */
    int dilatacion;  /* 1 = filtro sin huecos    */
} Nodo;

typedef void (*Kernel)(const Nodo *n);

/* Kernels de ejemplo: solo avisan cuál corrió. */
static void conv_esp_nn(const Nodo *n)
{ (void)n; puts("conv: ESP-NN (PIE)"); }
static void conv_referencia(const Nodo *n)
{ (void)n; puts("conv: referencia en C"); }
static void otro(const Nodo *n)
{ printf("operación %d\n", n->op); }

/* El despacho que hace la convolución de
   esp-tflite-micro: int8 sin dilatación va a ESP-NN. */
static void conv(const Nodo *n)
{
    if (n->es_int8 && n->dilatacion == 1)
        conv_esp_nn(n);
    else
        conv_referencia(n);
}

/* El "resolver": un kernel registrado por operación. */
static Kernel tabla[N_OPS];

void registrar(void)
{
    tabla[CONV] = conv;
    tabla[DEPTHWISE] = conv;   /* mismo despacho */
    tabla[PROMEDIO] = otro;
    tabla[SOFTMAX] = otro;
}

/* Una inferencia: cada nodo, en orden, una vez. */
void invocar(const Nodo *grafo, int n_nodos)
{
    for (int i = 0; i < n_nodos; i++)
        tabla[grafo[i].op](&grafo[i]);
}
