Decidir con la salida

De dos números por cuadro a una decisión estable: el puntaje, la histéresis, los votos, la precisión y el recall, y la supresión de cajas repetidas en un detector de objetos.

  • Explicar por qué un solo umbral hace parpadear la decisión y cómo lo evitan la histéresis y los votos.
  • Leer una matriz de confusión y calcular precisión y recall.
  • Explicar qué es el IoU y cómo la supresión de no máximos deja una caja por objeto.
  • Explicar por qué la exactitud cae con imágenes del lugar real.

El problema: dos números por cuadro

Al terminar la inferencia, el detector deja dos bytes: el puntaje de "hay persona" y el de "no hay persona". Llega uno nuevo cada 47 ms. Una persona que cruza la puerta puede dar 0,9 en un cuadro, 0,4 en el siguiente porque se movió, y 0,8 en el otro.

Si cada cuadro prendiera o apagara una luz, la luz parpadearía. Y la red se equivoca: según MLPerf Tiny, este detector acierta del orden del 86 % de las imágenes de prueba. La respuesta corta: pasar los bytes a un puntaje, usar dos umbrales en vez de uno y pedir que el cambio se sostenga varios cuadros.

La decisión vista desde afuera

Entra el tensor de salida de la red, cuadro tras cuadro. Sale una decisión, "hay persona" o "no hay", que cambia pocas veces, y una acción: prender un pin, mandar un aviso o despertar a otra parte del sistema.

Adentro: puntaje, umbrales y votos

La última capa del detector es un softmax: reparte una unidad entre las dos clases, así que los dos puntajes suman 1. En int8, la especificación de LiteRT fija su escala en 1/256 y su punto cero en −128. Entonces el puntaje es (q + 128) / 256: el byte 59 vale 0,73.

El umbral es el puntaje a partir del cual se decide "hay persona". El ejemplo de Espressif usa 60 %. Con un solo umbral, un puntaje que oscila cerca de 0,6 cambia la decisión en cada cuadro.

La histéresis usa dos umbrales: para pasar a "hay persona" el puntaje tiene que superar 0,7, y para volver, bajar de 0,5. Entre los dos, la decisión se queda como estaba. Así una oscilación chica no la mueve.

Los votos agregan memoria: el cambio se acepta solo si 3 de los últimos 5 cuadros lo piden. Un cuadro raro, por una sombra o un reflejo, pierde la votación.

analogía: el Schmitt trigger y el antirrebote

La histéresis es un Schmitt trigger: dos umbrales para que una señal ruidosa no haga conmutar la salida en cada cruce. Los votos son el antirrebote de un pulsador: el estado cambia solo si la entrada se mantiene varias muestras seguidas.

Recorrido: diez cuadros

Seguimos diez cuadros con puntajes 0,8; 0,2; 0,9; 0,6; 0,85; 0,6; 0,4; 0,3; 0,65 y 0,2. El estado empieza en "no hay persona".

  1. Cuadros 1 a 4. Superan 0,7 el 1 y el 3: son 2 de 5. No alcanza, y el estado sigue en "no hay". Con un solo umbral de 0,6, la luz ya habría prendido y apagado dos veces.
  2. Cuadro 5. Con 0,85 ya son 3 de los últimos 5 sobre 0,7. El estado pasa a "hay persona" y se actúa.
  3. Cuadros 6 a 9. Los puntajes bajan, pero en ninguna ventana de 5 hay 3 bajo 0,5. El estado se mantiene.
  4. Cuadro 10. Con 0,2, los cuadros 7, 8 y 10 están bajo 0,5. El estado vuelve a "no hay persona".

El costo es la demora: hacen falta al menos 3 cuadros para cambiar. A 47 ms por cuadro, la decisión llega unos 140 ms después que el primer cuadro con la persona.

Cómo se encadena: aciertos, errores y el lugar real

Ningún umbral elimina los errores; solo elige cuáles se prefieren. Una matriz de confusión cuenta los cuatro casos: personas detectadas, personas que se escapan, falsas alarmas y vacíos bien reconocidos.

El recall responde cuántas de las personas reales se detectaron. La precisión responde cuántas de las alarmas eran personas. Subir el umbral baja las falsas alarmas y sube la precisión, pero se escapan más personas y baja el recall. Una alarma de intrusos prefiere recall; un contador de visitas, precisión.

El 86 % de MLPerf Tiny se midió con imágenes de COCO reducidas a 96×96, donde cuenta como persona solo quien ocupa más del 2,5 % de la imagen. Una cámara en un pasillo oscuro, con otro ángulo o con gente lejos, ve otra cosa. Por eso la exactitud se vuelve a medir con imágenes del lugar, y el umbral se ajusta con ellas.

Detectores de objetos: una caja por objeto

El detector de personas es un clasificador: responde sí o no para toda la imagen. Un detector de objetos, como YOLO, devuelve muchas cajas, cada una con su posición y su puntaje. El mismo objeto suele aparecer en varias cajas casi iguales.

Para comparar dos cajas se usa el IoU (intersection over union): el área común dividida por el área que cubren entre las dos. Vale 1 si coinciden y 0 si no se tocan. La supresión de no máximos (NMS) ordena las cajas por puntaje, se queda con la mejor y apaga las que se le superponen más que un umbral; después repite con las que quedan.

En todas las arquitecturas la decisión corre en la CPU, aun con una NPU: el Ethos-U55 calcula la red, pero el umbral y la NMS son lazos con comparaciones y saltos, que hace mejor el procesador. En el detector de personas ese trabajo es despreciable; con cientos de cajas, la NMS ya se nota.

dato: estándares de evaluación

  • La evaluación de COCO mide los detectores con el mAP, que promedia la precisión para umbrales de IoU de 0,5 a 0,95.
  • MLPerf Tiny fija el conjunto de prueba y la exactitud mínima: 80 % para el detector de personas.

Relación con el resto del micro

La acción final es un pin o un mensaje: el pin del Microcontroladores, Tomo 2, nivel 1 o una transmisión por radio, que cuesta energía (nivel 7). La tarea que decide comparte la CPU con la inferencia, así que su tiempo entra en la cuenta del nivel 4.

Los números que importan

cálculo: del byte al puntaje

p = (q − z) · s

q
59, el byte de "hay persona"
z
−128, punto cero de softmax en int8
s
1/256, escala de softmax en int8

p = (59 + 128) / 256 ≈ 0,73; el otro puntaje vale 1 − 0,73 = 0,27

Con el umbral de 60 % del ejemplo, este cuadro cuenta como "hay persona".

cálculo: cuánto filtran los votos

P = 10 · e³ · (1 − e)² + 5 · e⁴ · (1 − e) + e⁵

e
1 % de cuadros vacíos con puntaje alto (supuesto)
supuesto
los errores de cuadros distintos son independientes

P = 10 · 10⁻⁶ · 0,98 + 5 · 10⁻⁸ · 0,99 + 10⁻¹⁰ ≈ 9,9 · 10⁻⁶ ≈ 0,001 %

La votación baja la falsa alarma de 1 % por cuadro a del orden de 0,001 % por ventana. En la práctica los cuadros vecinos se parecen, los errores no son independientes y la mejora es menor.

cálculo: el IoU de dos cajas

IoU = Acomún / (A1 + A2 − Acomún)

caja 1
de (10, 10) a (50, 50): 1600 px²
caja 2
de (30, 30) a (70, 70): 1600 px²
común
de (30, 30) a (50, 50): 400 px²

IoU = 400 / (1600 + 1600 − 400) = 400 / 2800 ≈ 0,14

Con un umbral de 0,5 las dos cajas sobreviven: la NMS las considera objetos distintos.

Límites y datos por confirmar

Los umbrales de 0,7 y 0,5 y la ventana de 5 cuadros son ejemplos: se ajustan con datos del lugar. La matriz de confusión es supuesta, armada con la exactitud publicada. Quedan por confirmar estos puntos:

  • la exactitud del detector en un lugar concreto, que hay que medir con imágenes propias;

  • cuánto tarda la NMS en el ESP32-S3 con muchas cajas.

para llevar

  • El puntaje sale del byte con la escala y el punto cero de softmax: (q + 128) / 256.
  • La histéresis usa dos umbrales y los votos piden que el cambio se sostenga: la decisión deja de parpadear a cambio de unos 140 ms de demora.
  • Recall: cuántas personas se detectaron. Precisión: cuántas alarmas eran personas. El umbral cambia una por la otra.
  • El 86 % vale para el conjunto de prueba: en el lugar real hay que volver a medir.
  • Un detector de objetos devuelve muchas cajas; la NMS deja una por objeto usando el IoU.

Lo probé con los diez cuadros de la figura 6.2 (el estado sube en el cuadro 5 y baja en el 10), con las cajas del cálculo (IoU de 0,14) y con las tres cajas de la figura 6.4.

ver el código 
#include <stdint.h>

/* De la salida de la red a una decisión. */

/* Softmax int8: escala 1/256 y punto cero -128 (LiteRT). */
float puntaje(int8_t q)
{
    return (q + 128) / 256.0f;
}

/* Histéresis y votos: "hay persona" sube si 3 de los
   últimos 5 cuadros pasan 0,7 y baja si 3 de 5 quedan
   bajo 0,5. Entre los dos umbrales no cambia nada. */
typedef struct {
    uint8_t altos, bajos;   /* últimos 5, un bit c/u */
    int hay_persona;
} Filtro;

static int unos(uint8_t b)
{
    int n = 0;
    for (; b; b >>= 1)
        n += b & 1;
    return n;
}

int filtrar(Filtro *f, float p)
{
    f->altos = ((f->altos << 1) | (p > 0.7f)) & 0x1F;
    f->bajos = ((f->bajos << 1) | (p < 0.5f)) & 0x1F;
    if (!f->hay_persona && unos(f->altos) >= 3)
        f->hay_persona = 1;
    else if (f->hay_persona && unos(f->bajos) >= 3)
        f->hay_persona = 0;
    return f->hay_persona;
}

/* Cajas de un detector de objetos: esquinas y puntaje. */
typedef struct { float x1, y1, x2, y2, p; int viva; } Caja;

static float area(const Caja *c)
{
    return (c->x2 - c->x1) * (c->y2 - c->y1);
}

/* IoU: área común sobre área total de las dos cajas. */
float iou(const Caja *a, const Caja *b)
{
    float w = (a->x2 < b->x2 ? a->x2 : b->x2) -
              (a->x1 > b->x1 ? a->x1 : b->x1);
    float h = (a->y2 < b->y2 ? a->y2 : b->y2) -
              (a->y1 > b->y1 ? a->y1 : b->y1);
    if (w <= 0 || h <= 0)
        return 0;
    float comun = w * h;
    return comun / (area(a) + area(b) - comun);
}

/* NMS: la caja con más puntaje gana y apaga a las que
   se le superponen más que el umbral. */
void nms(Caja *c, int n, float umbral)
{
    for (int i = 0; i < n; i++)
        c[i].viva = 1;
    for (;;) {
        int m = -1;
        for (int i = 0; i < n; i++)
            if (c[i].viva == 1 && (m < 0 || c[i].p > c[m].p))
                m = i;
        if (m < 0)
            return;
        c[m].viva = 2;                 /* elegida */
        for (int i = 0; i < n; i++)
            if (c[i].viva == 1 && iou(&c[m], &c[i]) > umbral)
                c[i].viva = 0;         /* suprimida */
    }
}
